# 压缩并上传素材

使用者是市场部同事，不熟悉 GitHub 和命令行。全程用简短的中文说明，每一步告诉他们正在做什么、结果如何。不要让他们自己敲命令。

压缩 = 图片长边缩到 2000 像素以内，转成 JPG（质量 85）；有透明背景的图保持 PNG。保留色彩配置文件，旧版 Office、WPS、微信都能打开。网页、PPT、销售资料使用足够清晰，但**不适合印刷**，也不适合大幅裁剪放大。PDF、视频和 brand/logo/ 下的 Logo（任何格式）不受影响，Logo 始终保持高清。

所有操作都通过 `python scripts/upload.py` 完成，不要直接运行 git 命令，不要修改 `scripts/`、`.github/`、`categories.yml`。

## 先判断是哪一种

| 用户说的 | 模式 | 参数 |
| --- | --- | --- |
| 「压缩并上传素材」「压缩上传」 | 只压缩**这次新放进去**的图片，然后上传 | `--compress` |
| 「整体压缩」「把仓库图片都压缩一下」「空间不够了」 | 把**仓库里所有**原图一次性压缩并上传 | `--compress-all` |

拿不准时问一句：「是只压缩这次新放的图片，还是把仓库里所有图片都压缩一遍？」

## 模式一：压缩并上传（--compress）

1. 检查：

   ```
   python scripts/upload.py check --compress
   ```

   用一张表告诉用户：文件、型号、语言、压缩前大小、上传后的文件名。环境问题、「需要先处理的问题 ✗」、「待上传」里未归类文件、没有新素材的处理方式与 upload-assets 相同。

2. 写描述：按 upload-assets 的「2. 写描述」步骤，对 `python scripts/upload.py describe-missing` 列出的文件逐个看图写一句描述并保存（压缩不影响描述，改名后描述会自动跟过去）。

3. 用户最初就说了「压缩并上传」时，写完描述直接上传；否则先问一句。

   ```
   python scripts/upload.py push --compress
   ```

   超时时间设长一些（例如 30 分钟），把每一步用一句话转述。

4. 汇报：上传了哪些文件和视频、每张图片压缩前后的大小（脚本会打印「7.9 MB → 0.2 MB」这样的结果）、在哪里看、注意事项。

## 模式二：整体压缩（--compress-all）

这是一次性的大操作，**必须先确认**。

1. 预览：

   ```
   python scripts/upload.py check --compress-all
   ```

   告诉用户有多少张图片会被压缩（预览里的条目数），并说明三件事，然后问「确认整体压缩吗？」：
   - 压缩后图片长边不超过 2000 像素，原图不再保留在当前版本里
   - 原来是 PNG（无透明背景）、TIFF、BMP、WebP 的图会变成 .jpg，这些图片已发出去的下载链接会失效；原本就是 JPG 的链接不变
   - 仓库历史里仍保留原图，所以「克隆仓库」的下载量不会减少；如果目的是彻底减小仓库体积，需要管理员另外清理历史，请联系管理员

   预览里没有需要压缩的图片：告诉用户仓库图片都已是压缩后的格式，结束。

2. 用户确认后：

   ```
   python scripts/upload.py push --compress-all
   ```

3. 汇报：压缩了多少张图片、推送结果。

## 注意事项（挑相关的说）

- **有透明背景的 PNG 压缩效果有限**：为保留透明只缩小尺寸、不改格式，大图通常只能小到原来的 1/3 左右（实测 8.3 MB → 2.8 MB），不像普通照片能小到 1/10。汇报时如实说明。

- 需要印刷用的高清图时不要压缩，原图留在设计部存档。
- 仓库是公开的：未发布的新品、价格、客户信息不要上传。
- 其余注意事项、常见问题与 upload-assets 相同。
