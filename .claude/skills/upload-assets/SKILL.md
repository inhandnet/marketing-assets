# 上传素材（不压缩）

使用者是市场部同事，不熟悉 GitHub 和命令行。全程用简短的中文说明，每一步告诉他们正在做什么、结果如何。不要让他们自己敲命令。

本 skill **不压缩图片**：图片保持原格式、原大小上传，只把文件名改成规范名（补上型号和语言）。需要压缩时，用户会说「压缩并上传素材」，那是另一个 skill（compress-upload-assets）。

所有操作都通过 `python scripts/upload.py` 完成，**不要加 `--compress` 或 `--compress-all`**，不要直接运行 git 命令，不要修改 `scripts/`、`.github/`、`categories.yml`。

## 步骤

### 1. 检查

运行：

```
python scripts/upload.py check
```

把结果整理成一张简短的表告诉用户：

| 文件 | 型号 | 语言 | 大小 | 上传后的文件名 |
| --- | --- | --- | --- | --- |

- 中文素材在 `zh/`，英文素材在 `en/`。
- 出现「环境检查 ✗」：照着提示处理（见下方「常见问题」），处理好再继续。
- 出现「需要先处理的问题 ✗」：逐条用大白话解释原因和改法，**停下来**，等用户处理后重新检查。
- 「待上传」文件夹里还有未归类的文件：**不要自己把它们放进型号文件夹**。改按 sort-assets 的步骤整理（读取 `.claude/skills/sort-assets/SKILL.md`，严格遵守其中「型号的依据」硬规则：没有依据的文件一律留在原处并问用户），整理确认后再继续上传。
- 没有发现新素材：告诉用户文件应该放在哪里（见下方「文件放在哪」），结束。
- 有单张超过 10 MB 的图片：顺带提一句「图片较大，如需压缩可以说『压缩并上传素材』」，但不要替用户决定，按不压缩继续。

### 2. 写描述（让 AI 和同事能按内容找到素材）

运行：

```
python scripts/upload.py describe-missing
```

对列出的每个文件写一句描述，再用下面的命令保存（文件路径照抄列表里的）：

```
python scripts/upload.py describe "<文件路径>" "<描述>"
```

- **图片**：用 Read 打开图片看一眼再写。**PDF**：读第一页再写。
- **PDF 是工程版规格书时先停下**：第一页是「产品规格书 / Datasheet」或文件名含「规格书 / Datasheet」，问用户「这像是工程版规格书，已经在 documents 仓库里了。是市场部设计的彩页版吗？」，确认是彩页版才继续，否则请用户移走后重新检查。
- **图上的型号和文件夹不一致时先停下**：比如放在 IR302 文件夹，但面板上印的是别的型号，告诉用户并确认，不要直接上传。
- **语言跟文件夹走**：`zh/` 下写中文，`en/` 下写英文。同一张图中英文各一份时，两边各写一句。
- **写什么**（一句话，中文不超过 60 字、英文不超过 30 个词）：画面里是什么（型号 / 方案 / 部件），什么角度或形式（正视、场景、组合图、Logo），背景（白底 / 场景 / 透明），图上有没有文字、什么语言，适合什么用途。
- **只写看得见的**：不编参数、卖点和数字；型号只写图上能读到的或文件夹的型号名，看不清就不写。
- **背景以列表为准**：列表里每张图后面的 `[尺寸，透明背景 / 不透明]` 是程序判断的。透明图在预览里看起来像白底，写描述时一律按列表写「透明背景」，不要写成白底。
- **视频**：看不了内容。列出视频后问用户一句「这个视频大概讲什么？一句话就行，不知道可以跳过」，用户回答了就保存，跳过就不写。

保存后把描述列成一张表给用户看，告诉他们「描述会随素材一起上传，有不准确的直接告诉我改」。用户要改就重新运行 `describe` 覆盖。

### 3. 上传

用户最初的请求就是上传时，检查通过后直接上传，不用再确认；用户只说"检查"时，问一句「检查没问题，现在上传吗？」。

运行（视频较大时会比较久，超时时间设长一些，例如 30 分钟）：

```
python scripts/upload.py push
```

上传过程中，把脚本输出的每一步（同步、上传视频、规范文件名、推送）用一句话转述给用户。

### 4. 汇报结果

简短告诉用户：

- 上传了哪些文件、几个视频（图片按原图上传，未压缩）
- **访问地址**：把脚本最后列出的「访问地址」整理成一张表给用户，每个文件一行：

  | 文件 | 查看（GitHub 页面） | 下载（直接下载链接） |
  | --- | --- | --- |

  脚本列出了「国内下载」时，表格再加一列「国内下载」。
  链接原样照抄，不要改写或省略。告诉用户：「查看」能预览和下载；「下载」链接可以直接发给同事或客户；「国内下载」是国内镜像，几分钟后才能打开，发给国内同事和客户更快。视频的「查看」是对应的 Release 页面
- 仓库是公开的，链接任何人都能打开（脚本如果提示"仓库目前是私有的"，就照实告诉用户只有有权限的人能打开）
- 素材画廊（按品类浏览、带缩略图）：中文 https://inhandnet.github.io/marketing-assets/_generated/gallery/zh.html ，英文把 zh.html 换成 en.html；上传后几分钟更新
- 几分钟后 GitHub 会自动更新素材清单
- 脚本最后列出的「注意事项」逐条转述并说明怎么处理

## 文件放在哪

```
zh/                                  中文素材（en/ 结构完全相同）
├── products/<型号>/                 产品素材，型号与官网一致
│   ├── images/                      产品图、场景图、海报
│   ├── brochures/                   宣传册、彩页规格书（PDF）
│   └── videos/                      视频（上传时自动传到 Release，不进仓库）
├── solutions/<方案>/                解决方案素材，方案名见 categories.yml 的 solutions
│   └── images/  brochures/  videos/ （同上）
└── brand/                           品牌资料（不分型号）
    ├── logo/                        Logo（可放 AI / EPS / SVG 矢量文件）
    ├── vi/                          VI 规范、品牌手册
    ├── templates/                   PPT、Word 模板
    ├── company/                     公司介绍、画册、资质荣誉
    └── videos/                      公司宣传片
```

- 没有文字的产品图、Logo 等，中英文各放一份。
- 型号、方案文件夹名与官网一致即可，大小写、空格、连字符都没关系。
- 可用的方案名读 `categories.yml` 里对应语言的 `solutions`（中文名在 `solution_names`），每周从官网自动同步。
- 文件夹名写法不规范（如 `MO62A`、`mo 62a`、`iwos`）没关系，上传时会自动统一成官网写法；同一型号有多个写法的文件夹会自动合并。
- 文件名随意，程序会自动加上前缀和语言：产品用型号、方案用方案名、品牌资料用 InHand，如 `InHand_logo_ZH.png`。

## 注意事项（挑相关的说，不要全部堆给用户）

- 仓库是公开的：未发布的新品、价格、客户信息不要上传。
- 图片按原图上传，上传后会一直保留在仓库历史里；单个文件超过 20 MB 会收到提醒。
- 设计源文件（PSD、AI 等）、3D 图纸、压缩包不上传。
- 视频单个不超过 2 GB；国内网络上传大视频可能较慢，中断了重新说一次「上传素材」即可，已上传的不会重复传。
- 上传后的视频本地文件会移到 `.已上传视频/` 留底，确认没问题后可以自己删除。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| git 或 gh 未安装 | 请 IT 安装 Git for Windows 和 GitHub CLI |
| GitHub 未登录 | 让用户在终端运行 `gh auth login`，选 GitHub.com → HTTPS → 用浏览器登录 |
| 缺少 Python 依赖 | 运行 `pip install pillow pyyaml` |
| 推送失败、网络错误 | 检查网络（或公司代理）后重新说「上传素材」 |
| 型号不在官网产品列表 | 确认型号拼写；该型号只在另一种语言官网上架时，确认是否放错了 zh / en |

## 补全素材描述

用户说「补全素材描述」「补描述」时（比如网页上传的素材没有描述，或检查报告提示有素材缺描述）：

1. 运行 `python scripts/upload.py describe-missing --all`，列出仓库里所有没有描述的素材。
2. 告诉用户一共多少个；超过 30 个时先问「一次补完，还是先补某个型号 / 栏目？」。
3. 按上面「2. 写描述」的规则逐个写（视频照样问用户，可跳过）。
4. 把写好的描述列表给用户看，确认后运行 `python scripts/upload.py push` 上传（只有描述改动也可以上传）。
