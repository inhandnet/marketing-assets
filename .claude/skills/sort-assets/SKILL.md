# 整理素材

使用者是市场部同事，不熟悉 GitHub。他们把文件随手丢进仓库根目录的 `待上传/` 文件夹，你负责判断归属并放好。全程用简短的中文说明。

只用 `python scripts/upload.py place` 移动文件，不要手动移动、改名或删除文件，不要运行 git 命令。

## 步骤

### 1. 盘点

列出 `待上传/` 里的全部文件（包括子文件夹）。为空就告诉用户把文件放进 `待上传/` 文件夹后再说「整理素材」，结束。

读取 `categories.yml`，了解中文官网（`zh`）和英文官网（`en`）各有哪些型号；`display_names` 是部分型号的中文名（如 `InCloud-Manager: 小星云管家`）。两个官网的产品线不完全相同。

### 2. 判断每个文件

**先判断归到哪一栏**：

| 栏目 | 什么文件 | 例子 |
| --- | --- | --- |
| 产品 `products/<型号>/` | 与某个具体型号相关 | IR315 宣传册、EC5350 场景图 |
| 解决方案 `solutions/<方案>/` | 介绍某个行业方案，不只是一款产品 | IWOS 方案介绍、AI 售货柜系统视频、xEnergy 案例 |
| 品牌资料 `brand/<子文件夹>/` | 公司层面，不属于任何型号或方案 | Logo、VI 手册、PPT 模板、公司介绍画册、公司宣传片 |

方案没有固定列表，方案名就是 `zh/solutions/`、`en/solutions/` 下的文件夹名：先看已有的方案文件夹，属于其中某个方案就用它的名字；是新方案时，跟用户确认一个英文方案名（如 `Smart-Factory`），中英文用同一个名字。品牌资料的子文件夹固定为：
`logo`（Logo，可含 AI/EPS/SVG 矢量文件）、`vi`（VI 规范、品牌手册）、`templates`（PPT、Word 模板）、`company`（公司介绍、画册、资质荣誉）、`videos`（公司宣传片，视频会自动归到这里）。

**类型**（产品、方案栏目）：看扩展名。
- 图片（jpg、png、webp 等）→ images
- PDF、PPT、Word → brochures
- 视频（mp4、mov 等）→ videos
- PSD、3D 图纸、压缩包等 → 不上传，告诉用户原因（AI / EPS 矢量 Logo 例外，放 brand/logo）

**型号 / 方案**，按可靠程度依次看：
1. 文件名里的型号，如 `IR315宣传册.pdf`、`ec5350 场景.jpg`
2. 子文件夹名，如 `待上传/IR315/xxx.jpg`
3. 文件名里的中文产品名，对照 `display_names`
4. 图片上**能清楚读到的型号文字**（如面板上印的 "IR302"）；PDF 第一页标题里的型号
5. 以上都没有 → 标记为「待确认」，**必须问用户**

> **硬规则：型号的依据只能是上面 1–4 条之一，或用户明确告诉你。**
> 「外观像某个型号」「和另一张图很像」「同系列的产品长得差不多」都**不算依据**——很多型号外观相近，猜错会以错误的型号公开。
> 没有依据的文件**一律不放**（不运行 place），留在「待上传」里列给用户，即使用户说了"不用问我、直接处理"也一样。
> 给用户的确认表里，「依据」一栏必须写出是哪一条（如「文件名含 IR302」「面板印有 IR302」「用户告知」）。

**语言**：
- 文件名或子文件夹含「中文」「CN」「ZH」→ zh；含「English」「EN」→ en
- 宣传册：读第一页，正文是中文就是 zh，英文就是 en
- 图片：打开看。**有文字**按文字语言；**没有文字**（纯产品图、场景图）→ `both`（中英文各放一份）
- 视频：文件名看不出时标记「待确认」
- 型号只在一种语言的官网上架时，语言多半就是那一种；与判断冲突时标记「待确认」

### 3. 给用户确认

用一张表展示判断结果，依据写清楚，拿不准的单独列出：

| 文件 | 归属（型号 / 方案 / 品牌） | 语言 | 类型 | 依据 |
| --- | --- | --- | --- | --- |
| IR315宣传册.pdf | IR315 | 中文 | 宣传册 | 文件名含型号；第一页为中文 |
| 产品图1.jpg | ？ | 中英文 | 图片 | 图片无文字；型号看不出 |
| logo.ai | 品牌 · logo | 中英文 | Logo | 文件名是 logo，矢量格式 |

- 全部确定：问一句「这样归类可以吗？」，用户同意后执行。
- 有「待确认」：只针对这些文件提问（可一次问多个），给出最可能的选项。
- 型号不在对应语言官网上：说明情况，问用户是否仍要放（确认后才加 `--force`）。方案不需要在官网上，新方案直接放。

### 4. 放进文件夹

同一归属、同一语言、同一类型的文件可以一次放：

```
python scripts/upload.py place "待上传/IR315宣传册.pdf" --lang zh --model IR315
python scripts/upload.py place "待上传/产品图1.jpg" "待上传/产品图2.jpg" --lang both --model IR315
python scripts/upload.py place "待上传/IWOS方案介绍.pdf" --lang zh --solution IWOS
python scripts/upload.py place "待上传/logo.png" "待上传/logo.ai" --lang both --brand logo
python scripts/upload.py place "待上传/公司宣传片.mp4" --lang zh --brand videos
```

- `--model` / `--solution` / `--brand` 三选一；`--brand` 取值 `logo`、`vi`、`templates`、`company`、`videos`
- `--lang`：`zh`、`en` 或 `both`
- 类型一般自动判断；特殊情况加 `--type images|brochures|videos`
- 出现「✗ 目标已存在」：问用户是替换还是改名，不要自行覆盖

放完后告诉用户每个文件去了哪里。

### 5. 上传

- 判断时已经打开看过的图片和 PDF，放好后顺手按 `upload-assets` 的「2. 写描述」规则把描述写好（`describe` 用放好之后的新路径），上传时就不用再看一遍。
- 用户说的是「整理并上传」：直接按 `upload-assets` 的步骤上传（不压缩）。
- 用户说的是「整理并压缩上传」或提到压缩：按 `compress-upload-assets` 的「压缩并上传」步骤上传。
- 否则问一句「已放好，现在上传吗？」，同意后按 `upload-assets` 的步骤上传（不压缩）。

## 注意

- 宁可多问一句，也不要放错型号或语言：放错后会以错误的名字公开。
- **工程版规格书不放这里**：PDF 第一页如果是「产品规格书 / Datasheet」、文件名含「规格书 / Datasheet」，先问用户：「这像是工程版规格书，它已经在 documents 仓库里了。如果是市场部设计的彩页版，确认后再放；否则不上传。」用户确认是彩页版才放。
- 不要上传未发布的新品、价格、客户信息；发现文件名或内容像是内部资料时提醒用户。
- 「待上传」里不能判断也不该上传的文件，留在原处，并告诉用户。
